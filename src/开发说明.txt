PDF 框选重命名 1.3.0 源码
许可证：AGPL-3.0-or-later，见 LICENSE.txt。

环境：Windows x64，Python 3.12；构建还需要可以访问 PyPI。

构建
在此 source 目录运行 PowerShell 脚本 build.ps1。
脚本创建隔离的 .venv，安装 requirements.txt，然后生成 dist\PDF框选重命名。
发布时需要携带整个生成目录以及使用说明、source 和 licenses。

测试
.venv\Scripts\python.exe make_samples.py
.venv\Scripts\python.exe -m pytest tests -q
make_samples.py 会在 source 的上级目录生成 test_documents 测试 PDF。

打包运行时诊断（操作临时副本，不改动传入文件）
PDF框选重命名.exe --self-test "测试PDF绝对路径" "报告JSON绝对路径"
报告目录须存在。诊断导出第一页 PNG、识别整页、在临时目录重命名并撤销，
校验原始文件的 SHA-256，最后生成 JSON 报告。正常退出码为 0。

报告审批打包自检：
PDF框选重命名.exe --self-test-reports "report_samples目录绝对路径" "报告JSON绝对路径"
使用五份随附测试报告的临时副本，验证后台预识别不改名、确认后改名、下一份候选及撤销。

结构
app.py：PySide6 界面、后台任务、坐标映射、过期结果过滤。
core.py：文件扫描、第一页渲染、中英文 OCR、安全重命名及撤销。
shortcuts.py：快捷键设置页面、冲突验证与原子写入用户配置。
ocr_processing.py：OCR 参数与持久化、局部对比度增强、黑白化与文本行倾斜纠正。
report_review.py：保留 OCR 位置，按文字锚点和编号格式提取、交叉核对、生成原始扫描截图。
report_ui.py：单任务后台队列、人工审批、跳过、冲突状态、文件指纹核对及撤销状态。
report_diagnostic.py：在临时样例副本中验证打包后的完整审批流程。
make_report_samples.py：生成没有文字层的虚构报告，覆盖偏移、倾斜、不一致及重复候选。
审批截图按逆变换映射回原始扫描图，增强和纠偏仅用于 OCR 输入。
预识别流程不调用重命名函数，只有确认按钮/快捷键进入改名流程。
1.2.2 的首位符号过滤按 Unicode 标点(P)或符号(S)类别判断，仅删除一个字符。
保留原始 OCR 候选，界面按开关状态生成显示与自动文件名，避免重复过滤。
切换文件清除选区，恢复 1.2.0 行为。
tests：核心与界面集成测试。
PDF 渲染与 OCR 使用同一个串行后台任务池，避免 MuPDF 并发调用。
预览按需渲染第一页；OCR 使用归一化选区的 clip，单独以 300/450/600 DPI 渲染，
限制选区长边 6000 像素及面积约 1200 万像素，不受整页尺寸上限影响。
PP-OCRv6 通过 rapidocr 3.10.0 的 ONNX Runtime 后端运行，显式指定本地 det/rec/cls，
保留 PP-OCRv4 旧模型，可分别识别或生成两个候选，不使用 PDF 文字层提取。
图像增强与纠偏只改变 OCR 输入，不修改 PDF 文件或页面预览。
OCR 模型与推理引擎通过 PyInstaller 收集并随软件提供。
